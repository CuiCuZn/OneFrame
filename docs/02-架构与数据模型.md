# 架构与数据模型

## 1. 进程与部署

```
浏览器 ──▶ FastAPI (127.0.0.1:8787)
             ├── /api/*        业务接口
             ├── /assets/*     构建后的前端静态资源
             ├── /             SPA fallback (frontend/dist/index.html)
             └── 后台 JobRunner（同进程 asyncio）
                    ├── HTTPX ──▶ 供应商 API
                    └── SQLite / data/media
```

- 单进程：API、任务执行、静态资源同一个 uvicorn 进程，`python backend/run.py` 一条命令。
- 开发模式：`cd frontend && npm run dev`（Vite 5173，`/api` 代理到 8787）。
- 没有 Redis/Celery：任务队列就是 SQLite 的 `jobs` 表，`JobRunner` 每 0.7 秒取一次 `queued`。
- 崩溃恢复：启动时把 `submitting/downloading/polling` 的任务标为失败（结果未知），把 `running` 且已有 `upstream_job_id` 的任务重新入队并只做轮询，不重新提交。

## 2. 数据模型（SQLite）

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `channels` | 供应商接入点 | `protocol`、`base_url`、`headers`、`enabled` |
| `channel_keys` | 密钥池 | `secret`(Fernet 密文)、`status`、`cooldown_until`、`fail_count`、`ok_count`、`last_used_at` |
| `models` | 用户可见的创作模型（厂商 × 模型） | `channel_id`、`upstream_model`、`modality`、`caps`、`params`、`price`、`overrides` |
| `jobs` | 生成任务 | `request`(快照)、`status`、`stage`、`progress`、`upstream_job_id`、`attempts`、`price`、`channel_id`/`key_id` |
| `assets` | 生成结果与上传 | `path`、`thumb_path`、`width/height`、`duration_ms`、`prompt`、`params`、`favorite`、`parent_id`、`root_id`、`tool`、`version` |
| `library_items` | 参考素材索引 | `source`、`external_id`、`kind`、`category`(二级分类)、`category_path`(完整路径)、`image_path`(绝对路径)、`thumb_path`、`depth_path`、`depth_thumb_path`、`has_depth`、`group_key`、`variant_label`、`search_text`、`nsfw` |
| `library_facets` | 参考素材的维度标签 | `item_id`、`field`（构图 / 姿势分类 / 角度 / 风格 / 主类 / 品类 / 颜色 / 单品 / 分区 / 发长 / 发型 / 视角 / 目录）、`value`、`level`(1 目录、2 子类、3 维度) |
| `prompts` | 提示词库 | `title`、`category`、`text`、`negative`、`tags`、`favorite`、`builtin` |
| `settings` | 本地偏好 | `default_image_model`、`library_roots` 等 |

约定：

- **一个模型 = 一个厂商 + 一个上游模型名**。同名模型在不同厂商下是两条独立记录，互不兜底。
- 所有 JSON 字段以 TEXT 存储（`caps` / `params` / `price` / `overrides` / `request` / `attempts` / `meta`）。
- 时间统一为 UTC ISO 字符串。
- `assets.path` 相对 `data/`，`library_items.image_path` 是绝对路径（允许目录之外的值不会被读取）。
- 唯一索引 `(source, external_id)` 保证重复导入幂等。

参考库分类在 `core/taxonomy.py` 中计算，导入时写入 `category` / `category_path` / `library_facets`，浏览时按 `library_facets` 做多级筛选（同一维度多选为「或」，不同维度之间为「且」）。规则版本记录在 `app_meta.library_taxonomy`，升级后启动会自动重建一次，也可手动运行 `python backend/reclassify.py`。

## 3. 任务生命周期

```
queued ──▶ submitting ──▶ running ──▶ succeeded
   │            │             │
   │            ├──▶ failed（参数/内容/5xx/超时，直接失败）
   │            ├──▶ uncertain（提交结果未知，保留上游任务号）
   │            └──▶ failed（401/403/429 只冷却 Key，不重发）
   └──▶ canceled（用户取消）
running ──▶ failed（上游失败/轮询超时）
running ──▶ canceled（下次轮询时停止）
```

- **图像**：OpenAI Images、Gemini 通常同步返回，`submit` 直接产出字节；窗口 900 秒。
- **视频**：`submit` 返回 `upstream_id`，`poll` 逐步更新 `progress`；窗口 2400 秒，超时进入 `uncertain`。
- **结果保存**：字节写入 `data/media/YYYY/MM/`，图片生成 WebP 缩略图，视频用 ffmpeg 抽封面并探测时长（缺失 ffprobe 时降级，不影响出片）。
- **重试**：失败/取消/待核对的任务可手动重试；自动流程不会换厂商或换模型。

## 4. 模型解析与密钥池

`POST /api/generate` 时同步完成：

1. **选定目标**：`model_id` → `channel_id` + `upstream_model`，没有候选集、没有二次选择。
2. **能力校验**：模型/渠道启用、媒体类型匹配、`max_refs`、`max_count`、`features`、画幅与清晰度（`aspect_ratio` / `resolution`）、视频参数枚举、协议自身校验。图像不再配置/提交 `size`，由适配器按画幅 + 1K/2K/4K 换算成具体像素尺寸。
3. **报价**：`per_image × count` / `per_second × duration` / `per_request`；任务成功后按该模型价格记账。

密钥选择（同一渠道、每次提交）：

```sql
SELECT * FROM channel_keys
WHERE channel_id = ? AND enabled = 1
  AND (cooldown_until IS NULL OR cooldown_until <= now)
ORDER BY fail_count ASC, COALESCE(last_used_at, '0000') ASC, ok_count DESC
LIMIT 1
```

失败类型决定冷却：

| kind | 触发 | 冷却 | 是否重试 |
| --- | --- | --- | --- |
| `auth` | 401/403 | 900s | 否（Key 冷却，下次任务换用） |
| `quota` | 429 | 120s | 否（Key 冷却，下次任务换用） |
| `params` | 400/404/422 | 0 | 否，直接失败 |
| `content` | 内容审核/安全拦截 | 0 | 否，直接失败 |
| `connect` | 连接失败 | — | 否，直接失败 |
| `upstream` | 5xx | — | 否，直接失败 |
| `network` | 读超时/协议中断 | — | 否，标记 `uncertain` |

**任何情况下都不会换到另一个厂商或另一个模型。**

> 安全阀：一旦请求可能已经到达上游，自动重发就可能产生两次计费。此时只保留任务号，由用户决定是否重试。Key 冷却只发生在 401/403/429，因为这类响应意味着请求没有被生成；单次任务仍然失败，不会在同一任务里换 Key 重发。

## 5. 参考图与提示词

- 参考图来源：`assets`（上传或历史作品）或 `library_items`（本地索引）。
- 提交前统一处理：`exif_transpose` → 超过 2048px 等比缩小 → 转 JPEG(92)，单任务总大小上限 30 MB。
- 角色：`character` / `costume` / `pose` / `style` / `reference`，进入 `POST /api/prompt/compile` 后编译为编号指令：

```
参考图对应关系：图1 = 人物外貌、图2 = 服装造型、图3 = 姿势构图。
• 人物：以图1的人物为准，保持脸型、五官、发型、发色与整体气质一致。
• 服装：让同一个人物穿上图2中的整套服装与配饰……不要复制其背景、陈列方式或模特外观。
• 姿势：参考图3的肢体姿态、重心、镜头角度与构图；只取姿势，不复制其外貌与服饰。
• 风格：电影剧照质感，柔和体积光与浅景深……
• 画面要求：<用户自由文本>
输出单画面、单人物、单视角……不要出现文字、标志与水印。
```

- 14 个风格预设（电影感、写实摄影、时尚大片、日系动画、厚涂、3D、水彩、赛博朋克、国风水墨、复古胶片、棚拍、角色设定、黑白硬光、无风格）。
- 编译结果写回输入框，用户可继续手改；服务端不保留隐藏状态。

## 6. 存储布局

```
data/
  oneframe.db        SQLite（WAL）
  secret.key         Fernet 主密钥（0600）
  media/2026/11/…    生成结果
  thumbs/…           缩略图（与 media 同构路径）
  uploads/202611/…   上传的参考图
```

- 删除作品会同时删除原文件与缩略图；删除参考库条目只删索引，不动磁盘文件。
- 备份 = 复制整个 `data/`（`secret.key` 与 DB 必须成对，否则密钥无法解密）。

## 7. 安全边界

| 面 | 措施 |
| --- | --- |
| 监听 | 默认 `127.0.0.1`，不对外暴露；无鉴权，公网部署需自行加反代与访问控制 |
| 密钥 | Fernet 加密落库；API 只返回 `sk-a••••••1234`；日志不打印密钥 |
| 路径 | 媒体读取限制在 `data/`；参考库读取限制在允许目录（data + 设置页目录 + env） |
| SSRF | 渠道地址由用户显式配置，仅允许 http/https；不跟随用户提供的任意 URL 下载（仅下载上游返回的结果地址） |
| 上传 | 单文件 25 MB、一次最多 8 个、按真实文件头判断 MIME |
| 注入 | 提示词只作为字符串传给上游；不拼接 SQL，参数全部绑定 |

## 9. 扩展一个新协议

1. 在 `backend/app/providers/` 新建类，继承 `Adapter`，实现 `validate` / `submit` / `poll`。
2. 声明 `protocol`、`label`、`modalities`、`supports_reference`、`param_keys`、`about`。
3. 在 `providers/__init__.py` 的 `ADAPTERS` 注册，并在 `PROTOCOL_DOCS` 补充默认地址。
4. 前端无需改动：协议列表、参数键、能力说明都会自动出现。

核心接口：

```python
class Adapter:
    async def submit(self, ctx: ProviderContext) -> SubmitResult: ...
    async def poll(self, ctx: ProviderContext, handle: SubmitResult) -> PollResult: ...
```

`ProviderContext` 提供 `client`（共享 httpx）、`base_url`、`api_key`、`headers`、`request`、`overrides`、`modality`。
